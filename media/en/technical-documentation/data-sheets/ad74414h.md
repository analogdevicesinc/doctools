## Quad-Channel, Software Configurable Input and Output with HART Modem

## FEATURES

- Quad-channel software configurable input and output
- Adaptive power switching reduces power dissipation by 40%
- Multiple configurable modes to a single pin
- Current input/output
- Digital input/output
- Overvoltage tolerant on screw terminal facing pins, powered or unpowered
- Auxiliary sense pins
- 10ppm/°C reference temperature coefficient
- 16-bit, Σ-∆ ADC with optional 50Hz and 60Hz rejection
- 14-bit monotonic DAC per channel
- Integrated HART ®  modem per channel
- On-chip diagnostics
- Open-circuit and short-circuit detection
- Voltage channel measurements
- Power supply measurements
- Internal temperature sensor, ±5°C accuracy
- SPI-compatible
- Addressable up to four devices
- Watchdog timer
- Wide power-supply range
- Temperature range: -40°C to +105°C
- Available in a 64-lead LFCSP

## APPLICATIONS

- Industrial control systems
- Process control
- Factory automation

## COMPANION PRODUCTS

- Voltage reference: ADR4525

- Flyback converter: MAX17691A, MAX17691B

## GENERAL DESCRIPTION

The AD74414H is a quad-channel, software configurable, input and output device for industrial control applications. The AD74414H provides a range of use cases integrated on a single chip. These use cases include analog input/output and digital input/output.

The AD74414H also has an integrated highway addressable remote transducer (HART) modem per channel. The input and output communications and the HART communications for all four channels are both supported using a single serial-peripheral interface (SPI).

The AD74414H provides two address pins to support up to four devices with a single SPI bus. SPI or general-purpose input/output (GPIO) pins can access the digital inputs/outputs to support higher data rates.

The AD74414H features a 14-bit digital-to-analog converter (DAC) per channel and a single 16-bit, Σ-∆ analog-to-digital converter (ADC). The AD74414H includes a high accuracy 2.5V on-chip reference that can serve as the DAC and ADC reference.

The AD74414H supports adaptive power switching, which allows the output stage to dynamically transition between two independent power sources. This transitioning ability saves up to 40% overall power consumption, thereby reducing dissipated heat in the module.

## TERMINOLOGY

## ADC Offset Error

For unipolar input ranges, ADC offset error is the deviation from the zero-scale code (0x0000) when inputs are shorted, 0V. The error is expressed in ppm FSR.

For bipolar input ranges, ADC offset error is the deviation from the midscale code (0x8000) when inputs are shorted, 0V. The error is expressed in ppm FSR.

## ADC Gain Error

Gain error applies to both unipolar and bipolar ranges. Gain error is a measure of the span error of the ADC.

For input ranges, gain error is defined as the full-scale error minus the zero-scale error. The error is expressed in ppm FSR.

## DAC Offset Error

Offset error is the deviation of the analog output from the ideal zero-scale output when the DAC output register is loaded with 0x0. The offset error is expressed in mV or μA in case of I OUT mode.

## DAC Gain Error

Gain error is a measure of the span error of the DAC. This error is the deviation in slope of the DAC transfer characteristic from the ideal expressed in % FSR.

## Total Unadjusted Error (TUE)

TUE is the total deviation of the output from the ideal. TUE includes INL, offset, and gain error.

## ROBUST ARCHITECTURE

The AD74414H system is robust in noisy environments and can withstand overvoltage scenarios such as miswire and surge events.

On-chip line protectors ensure that the I/OP screw terminal does not provide power to the IC when brought to a higher potential than the AVDD\_HI pin or AVDD\_LO supplies.

The recommended external components shown in Figure 27 and Table 34, which include the transient voltage suppressor (TVS), are selected to withstand surges on the input and output terminals.

With the recommended components, the I/OP and I/ON screw terminals tolerate overvoltages up to DC ± 36V (limited by the external TVS), when part is configured to any channel function.

A cyclic redundancy check (CRC) function is built into the SPI to ensure error free communications in noisy environments.

To enable the short-circuit diagnostic, use the DIN\_SC\_DET\_EN bit. Setting the DIN\_SC\_DET\_EN bit enables an additional 4mA of current sink. The system triggers a short-circuit fault if the 4mA sink limit exceeds.

Once an open-circuit or short-circuit fault triggers, set the appropriate bit in the ALERT\_STATUS register and assert the ALERT pin.

Program the DIN\_CONFIG0 and DIN\_CONFIG1 registers bits for Type 3D diagnostics, as follows:

- DIN\_SINK\_RANGE bit: 0x0
- DIN\_SINK bits: 0xF
- DIN\_OC\_DET\_EN bit: 0x1
- DIN\_SC\_DET\_EN bit: 0x1
- DIN\_THRESH\_MODE bit: 0x1
- COMP\_THRESH bits: 0x37

Programming these bits results in a typical current sink of 1.6mA and a rising voltage trip point of 8.5V, typically. The system triggers an open-circuit detection when sinking currents are less than 220µA. The system triggers a short-circuit detection when sinking currents are greater than typically 6.2mA.

## Short-Circuit Protection

Use a current-limit setting resistor, R SET , to achieve short-circuit protection when using digital output. The system triggers a shortcircuit event when the voltage across the resistor reaches the shortcircuit voltage, as shown in Table 6. In the event of a short-circuit, the DO\_SC bit is set in the CHANNEL\_ALERT\_STATUS[n] register, which in turn asserts the ALERT pin.

There is programmability around how the short-circuit behavior operates. The two configurable short-circuit timeout times are T1 and T2.

To support charging of large current loads on initial power-on of the digital output load, enable a higher short-circuit current limit for a programmable amount of time, T1. Turn on the digital output FET using the DO\_DATA bit to start T1 counting, even if no short-circuit event is triggered. If a short-circuit event occurs, the digital output FET remains on, clamped at the higher short-circuit current for the remainder of the programmed duration of T1. The short-circuit alert is not triggered during this time.

After T1 elapses, the system deploys a second short-circuit limit with a lower current limit and activate it for a programmable duration, T2. The T2 counter only starts counting if T1 expires and a short-circuit is detected. The FET remains on during a short-circuit event, but the current is limited to the lower short-circuit current for the programmed duration of T2.

The T2 counter is an up and down counter: when in short-circuit, the time increments. If the short-circuit condition goes away, the time count decrements.

Program the T1 and T2 in the DO\_EXT\_CONFIG[n] register. If the higher short-circuit current limit is not required, disable the T1. For the specified short-circuit values and T1 and T2 durations, see Table 6.

If the short-circuit continues to persist after the T2 time expires, the FET automatically disables. Once disabled, the relevant digital output timeout bit is set in the CHANNEL\_ALERT\_STATUS[n] register. The digital output disables, which reflects in the DO\_EXT\_CON-FIG[n] register.

Figure 38 shows the operation of the two programmable timeout times along with the short-circuit current limits.

1. Set the DO\_DATA bit to 0.
2. Choose a mode in the DO\_MODE bits in the relevant configuration register to power on the digital output circuit.
3. Set the DO\_DATA bit back to 1 to enable the FET.

## Configuring the AD74414H for HART Communications

To initiate the HART communications with the AD74414H, do the following steps:

1. Configure the channel in the appropriate function (current output with HART, current input loop powered with HART, or current input externally powered with HART).
2. Wait for channel initialization time (4.2ms for IOUT\_HART function or 300μs for others) before proceeding with another step.
3. Wait until HART compliant slew is settled (HART\_COMPL\_SETTLED bit set to high in the OUT-PUT\_CONFIGn register).
4. Enable the HART slew option SLEW\_EN to binary 10 (SLEW\_HART\_COMPL) in the OUTPUT\_CONFIGn register if the current output with HART is selected.
5. Power up the HART modem (MODEM\_PWRUP bit) in the HART\_CONFIGn register. Other HART configuration options are available in the HART\_CONFIGn register and a user can configure as required. Note that a duplex mode of operation is available to allow for loopback testing of the modem to confirm that a user can transfer and receive the data by the AD74414H.
6. Load the HART transmit first in first out (FIFO) with data required for transmission by the HART\_TXn register.
7. Clear the HART alerts in the HART\_ALERT\_STATUSn register.
8. Set the RTS bit (request to send) in the HART\_MCRn register to start HART transmissions.
9. Monitor the HART\_ALERT\_STATUSn register for status alerts on the progress of the HART communication.
10. Read the receive FIFO by using the HART\_RXn register. Note that the receive bytes of data are stored in the receive FIFO.

Setting the RTS bit once the TX FIFO is empty or before the HART modem power-up (setting the MODEM\_PWRUP bit) continuously transmits a 1200Hz sine wave to the modem's output when it is powered up. Clear the RTS bit manually to stop it.

During valid transmission (TX FIFO populated and HART modem powered up), the RTS bit is automatically cleared once the message transmission is completed unless the AUTO\_CLR\_RTS bit in the HART\_CONFIGn register is cleared.

## Communicating with the HART Modem

Communicate with the modem using the SPI. The SPI provides the necessary status bits to communicate with an existing software stack. The SPI manages the HART transactions and the software configurable input and output transactions.

It is also possible to configure the GPIO\_A pin, GPIO\_B pin, GPIO\_C pin, and GPIO\_D pin to either monitor or control the HART modem UART interface.

Control of the HART modem by GPIO is possible by configuring the HART\_GPIO\_IF\_CONFIG register. It is possible to control HART modem at one channel at the time.

Monitoring of the HART signals by GPIOs are fully interchangeable and available across all channels. Assign the HART signals to GPIOs by configuring the HART\_GPIO\_MON\_CONFIGn registers and its bit fields.

## Transmit and Receive FIFOs

The AD74414H is equipped with a HART transmit FIFO and HART receive FIFO. A user can store up to 32 bytes of data in each of the transmit and receive FIFOs.

Load the transmit FIFO by using the HART\_TXn register. Read the data from the receive FIFO by the HART\_RXn register. The system issues an alert if the number of bytes loaded to the transmit FIFO falls under the programmable threshold value. Similarly, the system issues an alert if the number of bytes loaded to the receive FIFO goes beyond the programmable threshold value. Program these receive and transmit threshold values by the TFTRIG and RFTRIG bits in the HART\_FCRn register.

The HART\_TFCn and HART\_RFCn registers record the number of bytes currently stored in the transmit and receive FIFOs, respectively. The user must manage the number of FIFO entries, exceeding entries above FIFO size results in data loss.

## HART Alerts

The HART\_ALERT\_STATUSn register contains all the alert bits associated with HART communications. If any bit asserts in the HART\_ALERT\_STATUSn register, then the HART\_ALERT\_x bit asserts in the ALERT\_STATUS register, which generates an interruption on the ALERT pin. Mask the HART alert bits by the HART\_ALERT\_x\_MASK register. If an alert bit is masked, it does not generate an interrupt on the ALERT pin when asserted, but a user can still see the alert in the HART\_ALERT\_STATUSn register.

## ADC\_RDY Functionality

The ADC\_RDY\_CTRL bit in the ADC\_CONV\_CTRL register determines the ADC\_RDY physical pin asserts. The ADC\_RDY pin asserts at end of the each conversions sequence or at the end of each conversion.

If only SPI monitors the ADC status, poll the ADC\_DATA\_RDY bit in LIVE\_STATUS register or ADC\_RDY bit in the readback SPI frame (see Table 32). Avoid polling any ADC result register.

The behavior of the ADC\_DATA\_RDY bit and the ADC\_RDY physical pin is not identical. In continuous conversion mode, ADC\_RDY pin automatically deasserts after 25μs, but a user must clear the ADC\_DATA\_RDY bit manually. Write 0b10 to the CONV\_SEQ bit field in ADC\_CONV\_CTRL register to clear the ADC\_DATA\_RDY bit. This does not interrupt the currently active continuous conversion. Clearing ADC\_DATA\_RDY bit also clears ADC\_RDY bit in the SPI readback frame.

To configure the ADC\_RDY pin asserting at the end of a sequence conversions, set the ADC\_RDY\_CTRL bit to 0. Read the resulting ADC data through ADC\_RESULT[n] and ADC\_DIAG\_RESULT[n]. Result registers update at the end of a sequence.

## DAC FUNCTIONALITY

The AD74414H contains a 14-bit DAC. The DAC core is a 14-bit string DAC. The architecture structure consists of a string of resistors, each with a value of R. The digital input code that is loaded to the DAC\_CODE register determines which node on the string the voltage is tapped off from and fed into the output amplifier. This architecture is inherently monotonic and linear.

There are two sources for the code loaded to the DAC. The typical option is to load a code to the DAC from the DAC\_CODE register. The second option is to enable slewing to control the rate at which the DAC code is loaded to the DAC.

## Digital Linear Slew Rate Control

The digital linear slew rate control feature of the AD74414H controls the rate at which the output transitions to the new value. This slew rate control feature is available for both the current and voltage outputs.

## RESET FUNCTION

After the AD74414H resets, all registers reset to the default state, and the calibration memory is refreshed. The device is configured in high impedance mode. A user can initiate the reset in several ways.

Pulse the RESET pin low to initiate the hardware reset. The RESET pulse width must comply with the specifications, as shown in Table 10.

Initiate a software reset by writing the 0x15FA code (Software Reset Key 1), followed by the 0xAF51 code (Software Reset Key 2), to the CMD\_KEY register. Software and hardware resets are identical in function and outcome.

Suppose a reset is required for all AD74414H devices connected to the same SPI interface, in such case, use the BROAD-CAST\_CMD\_KEY register. Initiate a software reset to all devices by writing the 0x1A78 code (Software Reset Key 1), followed by the 0xD203 code (Software Reset Key 2), to the BROAD-CAST\_CMD\_KEY register.

A user can also configure the thermal reset function, as shown in the Thermal Alert and Thermal Reset section.

A watchdog timer can generate the reset. For the description of the watchdog timer, see the Watchdog Timer section.

Low LDO1V8 or DVCC voltage triggers an internal power-on reset function that resets the AD74414H. The device remains in reset until the voltage at LDO1V8 and the DVCC is restored.

After a reset cycle completes, the RESET\_OCCURRED bit sets in the ALERT\_STATUS register. After the reset time elapses, clear relevant bits in the ALERT\_STATUS register before continuing to use the device.

If an SPI transfer attempts before the reset cycle completes (for the typical reset time, see Table 9), the SUPPLY\_ALERT\_STATUS register sets the CAL\_MEM\_ERR bit to indicate that the calibration memory is not fully refreshed, and the device must not be configured until the calibration memory load completes.

It is essential to ensure a proper refresh of the calibration memory. Reset the AD74414H if the CAL\_MEM\_ERR bit asserts.

Hardware, software, thermal, and watchdog-initiated resets have identical functionality, resulting in a reset of the AD74414H.

## FET LEAKAGE COMPENSATION

A software configurable input and output solution includes a precision analog input and output capability along with a high current, digital output capability on a single screw terminal. In the AD74414H, the external FET used in the digital output function may contribute in off-leakage to the screw terminal when not in use. The AD74414H has a FET leakage compensation feature that provides an alternative path to the FET leakage to prevent it from flowing in the I/OP\_x screw terminal (see Figure 26).

## FAULTS AND ALERTS

The AD74414H includes several fault monitors to detect an error condition.

If an alert or fault condition occurs, the ALERT pin asserts. The ALERT pin alerts not only of an fault or error condition, but it also incorporates various informative flags, especially in case of the HART modem.

To determine the source of the alert condition, read the ALERT\_ STATUS register. This register contains a latched bits of alert conditions and in other cases it points to alert source (HART\_ALERT\_x, CHANNEL\_ALERT\_x, SUPPLY\_ERR).

If CHANNEL\_ALERT\_x asserts, read the CHANNEL\_ALERT\_STA-TUS[n] register to determine alert source. When the SUPPLY\_ERR bit asserts, the SUPPLY\_ALERT\_STATUS register gives more insight concerning the alert source. The HART\_ALERT\_x bit indicates that alerts related to HART modem. Reading the HART\_ALERT\_STATUS[n] gives more insights.

After removing the cause of the alert condition, clear the activated flag by writing 1 to the location of the corresponding bits in the HART\_ALERT\_STATUS[n], CHANNEL\_ALERT\_STATUS[n], SUP-PLY\_ALERT\_STATUS, or ALERT\_STATUS. ## SPI

The AD74414H controls over a versatile 4-wire SPI, with a 2-bit address and an 8-bit CRC, operates at clock speeds of up to 20MHz (see the t 1 parameter in Table 10) and remains compatible with SPI, QSPI ™ , MICROWIRE ™ , and DSP standards. Data coding is always straight binary.

SPI is addressable for up to four devices. Addressable bits AD0 and AD1 determine address of the SPI subordinate node. Integrate the Address bits into the SPI frame to allow identification of each frame on the bus.

Drive the AD0 pin and AD1 pin with the correct logic levels to give a recognizable address to AD74414H by the connection of the AD0 pin and AD1 pin to the corresponding voltage level, either DGND or DVCC. Weak pull-down resistors internally connect address pins (AD0 and AD1) to DGND, which prevents the pins from floating when unconnected.

## SPI Read

Reading a register location requires two SPI frames. The process is called 2-stage readback. The 2-stage readback is divided into two stages: request and read stage.

The first SPI frame, transmitted during request stage, contains the address of the register to be read is written to the READ\_SELECT register. Table 31 shows the structure of the first SPI frame.

The second SPI frame, transmitted during read stage, contains of either a no operation (NOP) command or a write to any other register. The data is shifted out, MSB first, on the SDO pin:

- The MSB (Bit 39) is always set to 1 to allow the SPI main to detect if the SDO line is stuck low. This MSB is timed off the falling SYNC edge. Clock out all other bits on the SCLK rising edge. Bit 38 is always 0. Start frame sequence using 10 (Bit
- 39, Bit 38) allows the validation of the frame and provides an additional layer of error detection in a harsh environment.
- Bits[D37:D36] provide the information concerning the SPI device address set by the address pins (AD0 and AD1).
- Bits[D35:D32] provide the status information on the SDO pin concerning alerts and ADC\_RDY pin. For more details, see Table 32.
- Bits[D31:D24] provide the address of the register being read. Content of the READBACK\_ADDR bit field is shown in the READ\_SELECT register.
- The contents of the selected register are available in Bits[D23:D8].
- An 8-bit CRC is returned in Bits[D7:D0].

## Burst Read Mode

The AD74414H incorporates a burst read mode that allows sequential reading of multiple registers on the SDO pin, provided sufficient SCLKs are available.

To readback data from multiple registers, keep the SYNC line low after the second frame of a 2-stage readback (see the SPI Read section). The AD74414H increments through the register addresses clocking out the contents until the SYNC pin returns high. The device reports an SPI\_ERR error if the transaction does not end with 40 + (n × 24) SCLK rising edges, where n is the number of transactions.

Here is an example of how to complete a burst read of the ADC result registers of Channel A, Channel C, Channel D and Diagnostic 0:

1. Enable required BURST\_READ\_SEL bits in the BURST\_READ\_SEL register. In this case, set only BURST\_READ\_SEL[2], BURST\_READ\_SEL[4], BURST\_READ\_SEL[5], and BURST\_READ\_SEL[6] to 1. This allows a read in burst ADC\_RESULT0, ADC\_RESULT2, ADC\_RESULT3, and ADC\_DIAG\_RESULT0. Note that skip the register addresses disabled in the BURST\_READ\_SEL register, these addresses are not the part of the burst read output.
2. Set the READBACK\_ADDR bits in the READ\_SELECT register to 0x42 to read the first of the ADC results registers.
3. Provide a NOP command. Clock out the contents of the ADC\_RESULT0 register on the SDO pin and the CRC (standard readback frame).
4. Keep the SYNC pin low to provide an additional 24 clocks to allow for the 16 bits of data from the ADC\_RESULT2 register to be clocked out along with the 8 bits of the CRC.
5. Repeat step 4 two times. Keep the SYNC pin low to provide an additional 48 (2x24) clocks for another two registers ADC\_RE-SULT3 and ADC\_DIAG\_RESULT0.
6. Return SYNC high.
7. To read again same registers, repeat from step 2.

The SPI diagnostics include an SCLK count feature. The SPI accepts only SPI frames with exactly 40 SCLK falling edges as valid writes. In burst read mode, the number of SCLK rising edges must equal 40 + (n × 24), where n is the number of transactions.

## Watchdog Timer

The watchdog timer (WDT) feature reduces the risk of losing SPI communication by initiating reset that automatically configures all AD74414H channels into known high impedance mode.

Enable the WDT by setting WDT\_EN bit field in WDT\_CONFIG register. The first SPI transaction after the WDT enable initiates counting of the WDT timer. Each valid SPI frame transfer zeroes out the WDT. For instance, an SPI frame with an invalid CRC does not zero out the WDT. Reaching the defined timeout without an SPI transaction resets the AD74414H and sets the RESET\_OC-CURRED bit in the ALERT\_STATUS register to inform the user that a reset occurred. ## BOARD DESIGN AND LAYOUT CONSIDERATIONS

This section shows the critical board design and layout considerations for the AD74414H.

Track the SENSEHF\_x and SENSELF\_x filters directly to the pad of the R SENSE .

To guarantee stability for the CCOMP\_x pin, limit the capacitance to ground between the CCOMP\_x pin and the C COMP (if required) to &lt;10pF.

To guarantee stability for the VSENSEP\_x pin, limit the capacitance to ground between the VSENSEP\_x pin and the required 2kΩ resistor to &lt;10pF.

To optimize thermal performance, design the AD74414H boards with a minimum of four layers and with multiple thermal vias connecting the paddle to the bottom layer of the board. For more details, refer to the JEDEC JESD-51 specifications. Thermally connect the exposed pad of the AD74414H to the thermal vias.

When grounding the AD74414H pins, connect the AGND pins and DGND pins to a single ground plane. Connect the I/ON\_x screw terminal to the same ground plane.

Track the DO\_SRC\_SNS\_x pin directly to the pad of the external RSET . Considering the currents of the four digital output channels, use a star connection for DO\_VDD and R SET .

Limit SDO ground capacitance to achieve required SPI operation speed.
